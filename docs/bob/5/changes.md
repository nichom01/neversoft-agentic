# What has changed: #5 ui for sales orders

## Summary
A standalone React single-page application has been created in [`sales-orders-ui/`](sales-orders-ui) using Vite, React 19, and TypeScript. The application enables users to create sales order headers, validate inputs, add and delete order lines with real-time total calculations, select orders to view lines, and persist order data in browser `localStorage`. Complete local setup and running instructions are provided in [`sales-orders-ui/README.md`](sales-orders-ui/README.md) without modifying any existing workspace files or Java tests.

## Deviations from the plan
- **Node.js version is 22.12+, not 18+:** Vite 8.x and Vitest 5.x require Node `^20.19 || >=22.12`. [`sales-orders-ui/package.json`](sales-orders-ui/package.json) defines `"engines": { "node": ">=22.12.0" }`, and [`sales-orders-ui/README.md`](sales-orders-ui/README.md) reflects this requirement (checked by T-21).
- **Test tooling added to configuration:** Dev dependencies for Vitest (`vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `@types/node`), a `test` script, and `src/test-setup.ts` were added. [`sales-orders-ui/vite.config.ts`](sales-orders-ui/vite.config.ts) imports `defineConfig` from `vitest/config` to configure the test runner.
- **Latest package versions used:** Adopted React 19, Vite 8, TypeScript 7, and `@vitejs/plugin-react` 6 in accordance with project security dependency rules.
- **`npm run build` command scope:** `npm run build` runs `vite build`, while TypeScript checks are handled via `npm run typecheck` (`tsc --noEmit`).
- **Smoke script configurability:** [`sales-orders-ui/tests/smoke/smoke.sh`](sales-orders-ui/tests/smoke/smoke.sh) supports optional `SMOKE_PORT` (default `5173`) and `BASE_REF` (default `origin/main`) environment variables for flexibility in test execution.

## Risks and things reviewers should check
- **Browser storage vs API backend:** State is stored in browser `localStorage` under key `sales_orders_v1`. Reviewers should verify that [`sales-orders-ui/src/storage.ts`](sales-orders-ui/src/storage.ts) cleanly encapsulates data handling so that REST API integration can be swapped in without modifying UI components.
- **Input validation & number handling:** Check boundary condition handling in [`sales-orders-ui/src/components/OrderForm.tsx`](sales-orders-ui/src/components/OrderForm.tsx) and [`sales-orders-ui/src/components/OrderLineForm.tsx`](sales-orders-ui/src/components/OrderLineForm.tsx) (empty strings, whitespace, non-positive quantity, negative unit price, and floating-point precision).
- **Node runtime version:** Reviewers running tests locally should ensure Node.js >= 22.12 is active.
- **Project isolation:** Confirm that root project files and existing Java tests remain completely untouched.

## Follow-ups
- Align data models with Java domain models (e.g., Issue #4 domain models for sales orders) if a full-stack REST API backend is introduced.
- Add multi-currency or locale-aware currency formatting support if required beyond the standard 2-decimal presentation.
